# C5 - TypeORM Migration

## Goal

Generate a migration from the TypeORM entities, inspect its SQL, run it on an empty PostgreSQL database, revert it, and commit the migration file.

## 1. Build and Generate

```bash
npm run build
npm run migration:generate
```

Generate the initial migration only when one does not already exist. Do not delete or rename a migration after applying it.

## 2. Inspect the Migration

Open the generated file in `src/migrations/` and check that:

- `up()` creates `users`, `projects`, `project_members`, `tasks`, `tags`, `task_tags`, and `comments`.
- Foreign keys and their `ON DELETE` actions are correct.
- Required enum or check constraints exist.
- `project_members` uses `(user_id, project_id)` as its primary key.
- `task_tags` uses `(task_id, tag_id)` as its primary key.
- `down()` removes everything created by `up()`.

## 3. Run and Verify

```bash
npm run migration:run
psql -U postgres -d assignment1
```

Inside PostgreSQL, run:

```sql
\dt
\d project_members
\d tasks
\d task_tags
\q
```

You should see seven domain tables. TypeORM may also show its own `migrations` table.

## 4. Revert

```bash
npm run migration:revert
```

Run `\dt` again in PostgreSQL. The seven domain tables should be removed. The internal `migrations` table may remain, which is normal.

Optionally run the migration again to leave the database ready:

```bash
npm run migration:run
```

## 5. Commit

```bash
git status
git add src package.json package-lock.json tsconfig.json .env.example .gitignore
git commit -m "feat: add TypeORM entities and initial migration"
```

Do not commit `.env` because it contains your database password.

## Troubleshooting

If TypeORM says that an applied migration cannot be found, the database refers to a migration file that was deleted or renamed. Restore that exact file, or recreate the empty local database and generate one fresh migration.

## Checklist

- [ ] `npm run build` succeeds.
- [ ] The migration contains the correct tables and constraints.
- [ ] `migration:run` succeeds.
- [ ] `migration:revert` succeeds.
- [ ] The migration file is committed.
